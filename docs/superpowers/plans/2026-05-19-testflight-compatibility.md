# TestFlight Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare the UniWhereLiDAR Expo/React Native project so it can be built and submitted to Apple TestFlight via EAS.

**Architecture:** The project uses Expo SDK 54 with a bare workflow — the iOS native project does not yet exist (no `.xcodeproj`, no `Podfile`). Custom Swift native modules (LiDAR, ARKit) already live in `ios/UniWhereLiDAR/`. We will (1) declare the iOS deployment target and fix the new-arch / old-arch interop flag, (2) generate the Xcode project via `expo prebuild`, (3) wire the custom Swift files into the generated project via an Expo config plugin, (4) validate the build locally if macOS/Xcode is available, and (5) produce a signed `.ipa` via EAS and submit it to TestFlight.

**Tech Stack:** Expo SDK 54, React Native 0.81.5, EAS CLI ≥ 18.9.1, Xcode 16+ (macOS only), CocoaPods, ARKit, RealityKit, Swift 5.

## Task 4: Create Expo config plugin to include custom Swift sources

**Context:** After `expo prebuild`, the Xcode project (`.xcodeproj/project.pbxproj`) is generated fresh. The custom Swift files in `ios/UniWhereLiDAR/` will exist on disk but will NOT be referenced in the project — Xcode won't compile them. We need a config plugin that patches `project.pbxproj` to add all files under `ios/UniWhereLiDAR/` as compile sources. This plugin runs automatically during every `expo prebuild`.

**Files:**
- Create: `client/rn-arkit-replacement/plugins/withLiDARSources.js`
- Modify: `client/rn-arkit-replacement/app.json` (register the plugin)

- [ ] **Step 1: Create the plugins directory**

  ```bash
  mkdir -p client/rn-arkit-replacement/plugins
  ```

- [ ] **Step 2: Write the config plugin**

  Create `client/rn-arkit-replacement/plugins/withLiDARSources.js`:

  ```js
  const { withXcodeProject } = require('@expo/config-plugins');
  const path = require('path');
  const fs = require('fs');

  const LIDAR_GROUP = 'UniWhereLiDAR';
  const SOURCE_DIRS = ['Export', 'Mesh', 'Native', 'Scanning'];
  const TEST_GROUP = 'UniWhereLiDARTests';

  function collectSwiftFiles(dir) {
    if (!fs.existsSync(dir)) return [];
    return fs.readdirSync(dir)
      .filter(f => f.endsWith('.swift') || f.endsWith('.m'))
      .map(f => path.join(dir, f));
  }

  const withLiDARSources = (config) =>
    withXcodeProject(config, (cfg) => {
      const project = cfg.modResults;
      const iosDir = path.join(cfg.modRequest.platformProjectRoot);

      // Collect all source files
      const allFiles = [];
      for (const sub of SOURCE_DIRS) {
        const dir = path.join(iosDir, LIDAR_GROUP, sub);
        allFiles.push(...collectSwiftFiles(dir));
      }

      // Collect test files
      const testDir = path.join(iosDir, TEST_GROUP);
      const testFiles = collectSwiftFiles(testDir);

      const targetName = cfg.modRequest.projectName; // e.g. "UniWhereLiDAR"
      const target = project.pbxTargetByName(targetName);
      if (!target) {
        console.warn(`[withLiDARSources] target "${targetName}" not found — skipping`);
        return cfg;
      }

      for (const filePath of allFiles) {
        const relPath = path.relative(iosDir, filePath);
        project.addSourceFile(relPath, { target: target.uuid }, targetName);
      }

      // Add tests to the test target (name convention: "<AppName>Tests")
      // NOTE: Expo generates the test target with this exact name. If tests fail to
      // integrate after prebuild, run `grep "Tests" ios/*.xcodeproj/project.pbxproj`
      // to verify the actual target name and update testTargetName accordingly.
      const testTargetName = `${targetName}Tests`;
      const testTarget = project.pbxTargetByName(testTargetName);
      if (!testTarget && testFiles.length > 0) {
        console.warn(`[withLiDARSources] test target "${testTargetName}" not found but ${testFiles.length} test file(s) exist — they will NOT be compiled. Verify target name in project.pbxproj.`);
      } else if (testTarget) {
        for (const filePath of testFiles) {
          const relPath = path.relative(iosDir, filePath);
          project.addSourceFile(relPath, { target: testTarget.uuid }, testTargetName);
        }
      }

      return cfg;
    });

  module.exports = withLiDARSources;
  ```

- [ ] **Step 3: Register the plugin in `app.json`**

  Add `"./plugins/withLiDARSources"` to the `plugins` array in `app.json`:

  ```json
  "plugins": [
    [
      "expo-dev-client",
      {
        "launchMode": "most-recent"
      }
    ],
    "./plugins/withLiDARSources"
  ],
  ```

- [ ] **Step 4: Verify JSON is valid**

## Known Limitations

- **Simulator**: LiDAR scanning will fail on any iOS Simulator — this is expected. Always test scanning on physical LiDAR hardware.
- **New Architecture**: Native modules use `RCTBridgeModule` (Old Arch). `newArchEnabled` is disabled in this plan. Migrating to TurboModules is a separate task.
- **NSLocationWhenInUseUsageDescription**: ARKit may request location permission on certain configurations. If App Store review rejects for missing privacy string, add it to `app.json` under `ios.infoPlist`.
